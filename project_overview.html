01 — The problem

Predict credit approvals — then check whether the model treats people equally

The project does two things at once. First it builds a strong approval classifier from a deliberately anonymous dataset. Then it asks a harder question: when a model is accurate, does it still give different groups of applicants different chances?

🎯 Accurate prediction

Benchmark 13 algorithms under identical repeated cross-validation and pick the best by test AUC, not by memory of the training data.

⚖️ Fairness audit

Score every model on demographic parity, equal opportunity and equalized odds — with bootstrap intervals and permutation tests so gaps can be told apart from noise.

🧪 Mitigation test

Retrain three representative models without the protected attribute A1 and measure whether "unawareness" actually closes the fairness gaps.

Key insight: accuracy and fairness are not opposites here. The best-performing models are also among the fairest by equal opportunity, and the biggest gap — for age quartiles — comes from the data itself (true approval rates range from 34% to 63% across quartiles), not just the model.
02 — The data

UCI Credit Approval, with every attribute anonymised

The dataset contains 690 credit-card applications with 15 attributes and a binary approval outcome. Attribute names and values were renamed to meaningless symbols (A1…A15, values like t / f / a / b) so that the original meaning of each field is hidden.

Why anonymity matters for fairness

The columns cannot be named as gender, age or ethnicity. The audit therefore uses two anonymous grouping variables:

  • A1 — a two-level attribute (values a / b), widely interpreted as sex in the literature.
  • A2 quartile — applicants split into four equal-frequency age bands derived from A2.

The dashboard states this explicitly: the groups are anonymous proxies, not confirmed demographics.

04 — Exploratory data analysis

What actually drives an approval?

The EDA looks at class balance, continuous-attribute distributions by outcome, correlation, missing-value structure and one proxy relationship (prior default, A9) that turns out to dominate the model.

A9ApplicantsApproval rate
t36178.7%
f3297.0%

Clean-up decisions

  • Numeric missing values (A2, A14) → median imputation.
  • Categorical missing values (A1, A4, A5, A6, A7) → mode imputation.
  • Type coercion — nine columns converted to factors, six to numeric, target recoded to Approved / Rejected plus a numeric flag.
  • Skew — A15 spans 0 to 100,000, so it is log-transformed in feature engineering.
A9 dominates. A9 and its interaction with A10 (A9_and_A10) together carry more permutation importance than all the continuous credit attributes combined. Any fairness audit therefore has to ask whether A9 itself is a proxy for a protected group.

06 — Feature engineering

Stratified split, engineered features, and a crash diet for the predictor set

From 15 attributes to 20 candidate features

  • Split — stratified 80/20 → 553 train / 137 test applicants.
  • Imputation — medians and modes fitted on train only.
  • Log transforms — A3, A8, A11, A14, A15 (log1p) to tame skew.
  • Indicator flags — A11_pos, A15_pos for zero values.
  • Interaction — A9_and_A10 (both prior-payment flags true).
  • Ratio — A8_per_A2.
  • Age bands — A2_group quartiles (Q1–Q4), used for fairness evaluation, not prediction.

Selection pipeline

  1. Near-zero variance filter removes constant / near-constant columns.
  2. Correlation filter drops features with |r| > 0.90.
  3. Random-forest permutation importance (500 trees) keeps every feature with positive importance.
Result: 20 of 21 candidate features survive — only A12 has negative importance. A9 alone carries roughly 1.5× the importance of the next-best feature.

What the benchmark shows

  • Random Forest has the highest test AUC (0.918), closely followed by Elastic Net, LDA and Bagged Trees.
  • Bagged Trees wins on raw accuracy (86.1%) and F1 (0.848).
  • KNN and Naive Bayes trail clearly (AUC ≈ 0.83–0.84) — the only two models the statistical tests separate from the leader.
  • Most models land within ±0.005 AUC of each other, so "best" is a matter of arithmetic, not substance.
08 — Fairness audit

Three fairness definitions, measured for every model

Grouped by A1 (2 groups) and by A2 quartile (4 groups), each model is scored on the standard definitions from the algorithmic-fairness literature.

Demographic parity

Approval-rate gap — difference between the highest and lowest approval rate across groups. Ignores who truly deserved approval.

Equal opportunity

TPR gap — among applicants who truly were approved, does each group have the same chance of being approved by the model?

Equalized odds

Jointly checks the TPR gap and the FPR gap, so both correct approvals and false approvals matter.

How "real" a gap is measured

  • Bootstrap (B = 1,000) — 95% percentile intervals around every gap and around accuracy / AUC.
  • Permutation test (B = 2,000) — shuffle the group labels and record how large a gap appears by chance; the p-value is (null ≥ observed + 1) / (B + 1).
  • Chance reference — the average gap produced by random group assignment, shown in the dashboard.
  • Disparate-impact ratio — min / max approval rate (the "four-fifths rule" style ratio).
  • Holm adjustment — p-values are corrected across the model × group pairs.

Reading the results

  • A1 gaps are modest. For the top models the approval-rate gap is roughly 7–18 percentage points, with equal-opportunity gaps of 1–19 points.
  • Age quartiles are the bigger issue. Q4 has a 63% true approval rate versus 34% for Q1, so an approval-rate gap of ~0.27–0.37 appears almost everywhere — partly a base-rate effect.
  • Fairness ≠ accuracy. GBM and SVM Linear have the smallest A1 gaps but not the best AUC; Bagged Trees has the highest accuracy but one of the widest gaps.
  • After Holm adjustment, no equal-opportunity gap is significant — the intervals are wide and group sizes small (45 vs 92 applicants in the A1 split).

09 — Statistical significance

Is the best model really better, or is it luck on 137 applicants?

Random Forest is the reference (highest AUC) and is compared with every other model on the same 137 test applicants using two complementary paired tests.

DeLong test

Paired comparison of AUCs — tests whether the ranking quality differs. A large adjusted p-value means the two AUC curves cannot be distinguished.

Exact McNemar test

Counts applicants where exactly one model is right and runs an exact binomial test. Tests whether the models differ in raw classification.

10 — Mitigation

Does hiding the protected attribute make a model fair?

"Fairness through unawareness" is the simplest mitigation: remove A1 from the feature set and retrain. Three representative models are refit with and without A1 on identical folds.

Findings

  • Accuracy is unchanged — every variant keeps the same accuracy (82.5–83.9%), so dropping A1 costs nothing.
  • A1 fairness improves for Logistic Regression (EO gap 0.045 → 0.001) and Random Forest (0.193 → 0.124).
  • Age-quartile gaps barely move and even tick up slightly.
  • Elastic Net is completely unaffected — regularisation already zeroed out A1, so 0% of its predictions change.
Unawareness is a partial fix at best. The remaining gap comes from other attributes that correlate with the protected one — removing A1 does not remove its signal.
11 — Delivery

An interactive Shiny dashboard for the verdict

All audit outputs are packaged into a five-tab Shiny app with interactive Plotly charts, so a reviewer can explore the trade-offs themselves instead of reading a static report.

1 · Overview

AUC per model with 95% bootstrap whiskers, plus a test-set metrics table.

2 · Fairness by model

Pick a model, pick a split, see the gaps, the chance reference and the per-group approval / TPR bars.

3 · Accuracy vs fairness

Toggle between accuracy and AUC, equal-opportunity and approval-rate gaps, with error bars.

4 · Is the best model really better?

DeLong and exact McNemar comparisons against the reference model.

5 · Base rates & limitations

True approval rates by group, and an explicit list of limitations so the results are not over-claimed.

Engineering details worth noting

Fast gap computation

Bucketed tabulate() instead of loops makes 2,000 permutations × 12 models × 2 splits finish in seconds.

Robust to failures

Model training is wrapped in tryCatch; a failing algorithm (like XGBoost here) is logged and skipped instead of aborting the run.

Honest framing

The UI labels groups as anonymous and explains that a gap-bootstrap interval is skewed, recommending the chance comparison instead.

12 — Summary

What we learned

✔ Modelling

  • A9 (prior payment history proxy) is the single strongest predictor.
  • Ensembles (Random Forest, Bagged Trees) and regularised linear models dominate.
  • 12 models land between 0.78 and 0.92 AUC; only KNN is clearly worse.

✔ Fairness

  • A1 gaps are modest; age-quartile gaps are large but mostly base-rate driven.
  • No equal-opportunity gap survives Holm correction.
  • Fairness through unawareness helps A1 but not age — and costs nothing in accuracy.
